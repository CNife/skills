# Obsidian 日记与待办管理

将当前会话内容总结并写入 Obsidian 日记，同时搜索、更新、新增待办。

## 变体选择

根据会话内容判断使用哪个变体：

- **work** → 公司项目、部署运维、代码开发、正式会议、团队协作
- **personal** → 个人技术探索、学习笔记、投资、生活记录

混合内容时，拆分后分别写入两个变体。

确定变体后，读取对应的 references 文件获取路径、格式、风格规则：
- work 变体 → `references/work-log.md`
- personal 变体 → `references/personal-diary.md`

## 脚本

所有文件系统操作通过 `scripts/obsidian-helper.py` 完成，脚本路径相对于本 skill 目录。

```
python3 scripts/obsidian-helper.py --vault <work|personal> --action <action>
```

可用 action：
- `locate` — 获取今日日记路径、模板路径、存在状态
- `create` — 确保今日日记存在，不存在则从模板创建
- `todos` — 扫描近期日志，列出未完成待办
- `recent` — 列出近期修改的日志文件（支持 `--limit N` 限制数量）
- `read` — 读取指定文件或今日日记

## 工作流

### 步骤 1：定位并创建今日日记

```bash
python3 scripts/obsidian-helper.py --vault <变体> --action locate
```

根据输出判断：
- `DIARY_EXISTS=true` → 文件已存在，进入步骤 2
- `DIARY_EXISTS=false` → 执行创建：
  ```bash
  python3 scripts/obsidian-helper.py --vault <变体> --action create
  ```

### 步骤 2：读取近期上下文

```bash
python3 scripts/obsidian-helper.py --vault <变体> --action recent --days 10 --limit 10
```

读取 `--- RECENT ---` 下方列出的最近 2-3 篇日志，了解：
- 当前项目进展和待完成事项
- 写作风格（工作日志=简洁结构化，个人日记=轻松有观点）
- 避免重复记录已有内容

### 步骤 3：读取今日日记现有内容

```bash
python3 scripts/obsidian-helper.py --vault <变体> --action read
```

如果文件已有内容，在此基础上更新或合并；如果是新文件，直接写入。

### 步骤 4：搜索并更新待办

```bash
python3 scripts/obsidian-helper.py --vault <变体> --action todos --days 14
```

#### 4a. 更新已完成待办

对比本次会话完成的工作与 `--- TODOS ---` 列出的未完成待办：
- 如果匹配 → 将对应文件中的 `- [ ]` 改为 `- [x]`，并添加 `✅ YYYY-MM-DD`（今天日期）
- 同时在**今日日记**的对应任务下添加 Obsidian 链接指向原待办：
  ```
  - [x] 任务描述 ✅ 2026-04-17  完成于 [[2026年4月15日星期三##任务标题]]
  ```
  链接格式：`[[文件名#二级标题]]`，文件名不带路径和 `.md` 后缀

#### 4b. 新增今日待办

本次会话产生的新待办，统一添加到**今日日记**中：
- 按项目/主题分组（`# 项目名` → `## 任务名`）
- 新待办格式：`- [ ] 描述`
- 如果待办有明确的下一步计划日期，添加 `📅 YYYY-MM-DD`

#### 4c. 取消不再需要的待办

如果某项待办已不再需要：
- 将 `- [ ]` 改为 `- [-]`，并添加 `❌ YYYY-MM-DD`

### 步骤 5：写入日记内容

根据 references 文件中的格式规则，将本次会话内容写入今日日记。

**与原始命令的关键区别**：
- **可以更新已有内容**：如果本次会话对之前记录的任务有补充、修正或状态变更，直接修改对应段落
- **可以合并重复内容**：如果今日日记已有类似记录，合并而非重复追加
- **不修改与本次会话无关的内容**

写入方式：
- 如果今日日记是全新的 → 直接写入完整内容
- 如果今日日记已有内容 → 在末尾空一行后追加本次新增内容，同时更新已有段落中涉及本次会话的部分

### 步骤 6：确认

输出本次写入/更新的内容摘要，包括：
- 新增的工作总结条目
- 更新的待办（状态变化 + 链接）
- 新增的待办

如果本次没有实质性内容，询问用户是否仍要写入。

## AI 噪音过滤

禁止写入以下内容：
- 验证流程（"N 轮最终验证 APPROVE"、"XX 个测试用例全部通过"）
- 提交/推送操作（"已提交并推送到 XX 分支"）
- AI agent 产物（"沉淀 N 条规则到 AGENTS.md"）
- 开发阶段标记（Wave 1/2/3、"骨架创建"、"模块创建"）
- 配置文件路径、代码片段

只写：做了什么 + 核心特性/关键决策 + 关键结果。保留有价值的信息：人名、技术选型判断、关键数据。

## Obsidian 待办状态

使用 Tasks 插件标准状态：

| 标记 | 状态 | 用途 |
|------|------|------|
| `[ ]` | 待办 | 未完成的任务 |
| `[x]` | 已完成 | 完成的任务，末尾加 `✅ YYYY-MM-DD` |
| `[-]` | 已取消 | 不再需要的任务，末尾加 `❌ YYYY-MM-DD` |

可选状态（按需使用）：
- `[/]` 进行中 — 已开始但未完成
- `[>]` 延期 — 推迟到以后
- `[!]` 重要 — 高优先级
- `[?]` 疑问 — 需要确认
- `[h]` 搁置 — 等待外部条件

跨文件引用已完成待办时，使用 Obsidian 链接：`[[日期文件名#任务标题]]`
