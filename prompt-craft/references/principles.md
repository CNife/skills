# OpenAI 提示词工程最佳实践

来源：https://help.openai.com/zh-hans-cn/articles/6654000

## 原则 1：使用最新的模型

最新、能力最强的模型往往更容易做提示词工程。推理模型（如 o1、o3）与 GPT 模型的提示方式有差异。

## 原则 2：将指令放在开头，使用分隔符

使用 `###` 或 `"""` 将指令与上下文分隔开。

❌ `将下方文本总结为要点列表，列出最重要的几点。{text}`
✅ `将下方文本总结为要点列表，列出最重要的几点。Text: """{text}"""`

## 原则 3：具体、描述清晰、提供细节

在上下文、结果、长度、格式、风格等方面要具体。

❌ `写一首关于 OpenAI 的诗。`
✅ `写一首简短且鼓舞人心的 OpenAI 主题诗，重点围绕近期 DALL-E 产品发布，并以 {著名诗人} 的风格来写`

## 原则 4：通过示例阐明期望的输出格式

既要"展示"，也要"说明"——展示具体格式要求时模型响应更好，也更容易编程解析。

❌ `从文本中抽取实体：公司名称、人名、具体话题与主题。`
✅ `抽取实体。格式：公司名称: <逗号分隔> 人名: <逗号分隔> 具体话题: <逗号分隔> 总体主题: <逗号分隔>`

## 原则 5：零样本 → 少样本 → 微调

先尝试零样本（只给指令），效果不好再加 1-3 个示例（少样本），还不行再考虑微调。

## 原则 6：减少空泛和不精确的描述

❌ `这个产品的描述应当比较简短，只需几句话，不要再多太多。`
✅ `用 3 到 5 句话的一段文字来描述这个产品。`

## 原则 7：说应该做什么，而非只说不做什么

❌ `不要询问用户名或密码。不要复述。`
✅ `客服专员将尝试诊断问题并提出解决方案，同时避免询问任何 PII。不要询问用户名或密码，而是引导用户查看帮助文章。`

## 原则 8：代码生成专用——使用"引导词"

在代码生成的提示末尾加入 `import`、`SELECT` 等引导词，将模型推向特定模式。

❌ `# 写一个 python 函数，把英里转换为公里`
✅ `# 写一个 python 函数，把英里转换为公里\nimport`

## 原则 9：参数调优

- `model`：性能越高的模型越贵，延迟越高
- `temperature`：事实型用例（数据抽取、真实问答）设为 0；创意型可提高
- `max_completion_tokens`：硬截断上限，不是控制输出长度的方式
- `stop`：一组字符（token），生成到它们时停止
