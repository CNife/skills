# 用拷问的方式对齐未知

这是 `grill-with-docs` 的强化版：调用 Skill 工具两次，分别调用 `grilling` 和 `domain-modeling`；在它们的工作过程中，用四类未知事项探索战争迷雾。

## 核心图景

- **地图**：当前掌握的计划、假设、上下文和认知。
- **领土**：真实代码、产品约束、API、数据、运行环境、用户判断和失败方式。
- **战争迷雾**：4X 游戏中尚未探索、因而不可见的区域；在这里指地图与领土之间尚未探明的差距。
- **未知事项**：战争迷雾中的一项具体问题。
- **实质性未知事项**：答案可能改变计划、决定或最终结果的未知事项。清单只追踪这类事项。

## 流程

1. **复述地图**：说明当前目标、计划、假设和已经掌握的信息。
2. **核对领土**：先检查手边可用的文档、源码、测试和配置，再建立未知事项清单。需要系统调查外部一手资料并保存结论时，调用 Skill 工具并使用 `research`。
3. **建立完整清单**：始终显示以下四类，即使某一类暂时为空：
   - **已知的已知**：已经明确陈述，或已有证据支持的事项。
   - **已知的未知**：已经意识到尚待调查或决定的事项。
   - **未知的已知**：用户尚未说出，但看到具体结果就能作出判断的标准。
   - **未知的未知**：当前各方尚未意识到的约束或可能性。
4. **推进拷问**：遵循 `grilling` 的分轮方式。清单内容发生变化时，重新显示完整的四类清单；没有变化时不重复。
5. **按类分流**：
   - 未知的已知需要通过具体界面或行为显现时，调用 Skill 工具并使用 `prototype`；原型的形式和处理方式完全由该技能负责。
   - 遇到陌生领域、不熟悉的代码库区域或高风险集成时，进行一次**盲区侦察**：检查相关文档、源码和测试，特别留意关键依赖已知的限制和失败方式；按风险说明发现，并给出成本较低的查明办法。需要正式调查外部资料时使用 `research`。
6. **按需托管**：只有用户明确要求进入**托管模式**时，才为剩余的低风险事项选择默认答案，并集中交给用户否决。其余决定仍由用户作出。
7. **结束**：当每个实质性未知事项都已解决、采用默认答案或被明确接受为假设，未处理数量归零时，未知事项清单完成。随着数量减少，说明还剩多少项；最终保持剩余假设可见。随后继续遵循 `grilling` 的结束条件。

## 未知事项清单

每次显示都使用完整结构：

```md
## 未知事项清单

### 已知的已知

- <事项> — 证据：<来源>

### 已知的未知

- <事项> — 状态：未处理 / 已解决 / 已采用默认答案 / 已接受为假设

### 未知的已知

- <有待通过具体结果显现的判断标准> — 状态：未处理 / 已解决 / 已采用默认答案 / 已接受为假设

### 未知的未知

- <疑似约束或可能性> — 状态：未处理 / 已解决 / 已采用默认答案 / 已接受为假设
```

本技能不负责制定实施计划、执行改动、代码审查或验收实施结果。
