# 技能设计领域模型

这个上下文定义写技能时用的词。一个词对应一个概念；正文和参考文件都按这里的选择用词。

## 语言

### 结构

**技能**：
给 agent 的行为规格，由 `SKILL.md` 和它指向的参考文件组成；加载后改变 agent 的一次执行过程。
_避免_：文档、提示词、指南

**正文**：
`SKILL.md` 中随技能加载直接进入上下文的部分。
_避免_：主体、主文件、内容

**参考文件**：
技能目录下按需读取的文件，由正文的指针触达。
_避免_：引用、附件、附录、子文档

**指针**：
正文里指向参考文件或外部材料的一行，写明材料是什么、什么情况下读。
_避免_：链接、引用、跳转

**description**：
frontmatter 中决定 agent 能否自行发现这个技能的那段文字。
_避免_：描述、摘要、简介

### 角色与触发

**agent**：
加载并执行技能的执行者。
_避免_：AI、模型、助手

**人**：
技能的发起人和最终裁决者。
_避免_：用户、操作者、读者

**自动触发**：
description 对 agent 可见，agent 能自行加载，其他技能也能调用。
_避免_：模型调用、隐式调用

**手动触发**：
description 不对 agent 暴露，只有人点名才能加载，其他技能调不到。
_避免_：显式调用、用户调用

### 三类技能

**工具型**：
agent 缺工具的心智模型和状态时写的技能。
_避免_：能力型、API 型

**流程型**：
agent 缺稳定执行顺序和完成标准时写的技能。
_避免_：SOP 型、步骤型

**倾向型**：
agent 的默认反应不对、需要覆盖时写的技能。
_避免_：风格型、语气型

**重点**：
某一类技能正文必须承载的核心信息。
_避免_：要点、关键、核心

**心智模型**：
一个工具是什么、拥有什么状态、不是什么的一段描述；工具型技能的主体。
_避免_：概念介绍、原理

**适用范围**：
这个工具或这条规则该用、不该用的场景边界。
_避免_：使用场景、适用条件

### 成本

**上下文成本**：
自动触发的技能每轮占据上下文预算的代价。
_避免_：token 开销、提示词开销

**认知成本**：
人必须自己记住技能名称和用法的代价。
_避免_：学习成本、记忆负担

**路由技能**：
一个手动技能，列出其他手动技能及各自的使用场景，只能提示，不能代人触发。
_避免_：索引、目录

### 流程

**流程结构**：
流程的骨架，分线性、状态机、DAG 三种。
- **线性**：单一路径，没有回环和并行。
- **状态机**：有状态、分支、重试或等待人工。
- **DAG**：有依赖、并行或汇合。
_避免_：形状、形态、模式

**状态**：
某一刻的事实：谁持有资源、流程走到哪一步、是否失败。
_避免_：阶段、进度、情况

**转移条件**：
允许流程从一个状态走到下一个状态的事实。
_避免_：判断条件、guard、触发条件（「触发」只指技能加载）

**完成标准**：
判断一步、一份流程或一份技能是否做完的依据。
_避免_：完成条件、验收标准、definition of done

**失败态**：
流程或工具无法继续、也无法确认安全时所处的状态。
_避免_：失败点、错误、异常

**判断点**：
流程中必须由 agent 做决定、不能预写成脚本的一步。
_避免_：决策点、分支

**人工确认点**：
流程中必须由人做决定的一步，做完之后继续执行。
_避免_：checkpoint、审批点、human-in-the-loop

**事实源**：
状态、数据、规则的权威来源。
_避免_：真相、依据、来源

### 写作

**规则**：
技能中改变 agent 默认行为的一条指令。
_避免_：要求、约束、原则

**判据**：
在两个以上选项之间做选择时用的那条线。
_避免_：依据、条件（判断是否做完用「完成标准」）

**写坏的标志**：
某一类技能常见的失败症状，用于诊断。
_避免_：反模式、常见错误、坑

**改造检查**：
对已有技能做的跨类型复检：类型、重点、通用问题、臃肿。
_避免_：错位、审查清单

**脚本**：
技能目录中承担确定性动作的程序，自己处理错误并给出可操作提示。
_避免_：工具、命令、自动化

**脚本边界**：
把固定、可重复的动作交给脚本、把需要判断的动作留给 agent 的那条线。
_避免_：自动化边界、人机边界
