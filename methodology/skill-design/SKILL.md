# 技能设计

技能不是文档，是一次可预测的行为改变。**agent 缺什么，决定技能类型；每类的重点，决定正文；三个通用问题，决定它能不能执行。**

## 三类技能

| 类型 | agent 缺什么 | 重点 | 正文必须回答 | 常见写坏 |
|---|---|---|---|---|
| **工具型** | 不知道工具的接口、状态和边界 | 心智模型和状态 | 它是什么、不是什么；入口；状态归谁；失败时什么样；什么时候不该用 | 写成命令清单，没有状态模型，也没有「别手工做」的边界 |
| **流程型** | 步骤不稳、判断点不清 | 顺序和完成标准 | 每步做什么、做到什么算完；哪步交给脚本、哪步留给判断；事实源；人工确认点 | 把判断写死成脚本，或把固定步骤留给 AI；步骤没有完成标准 |
| **倾向型** | 默认反应不对 | 默认行为的覆盖 | 默认行为是什么；目标行为是什么，且可观察；什么时候适用；什么时候不适用 | 写成价值观散文，没有可观察的目标；规则不改变行为 |

### 工具型

先写心智模型，再写入口；先写状态归谁，再写命令。命令是最后的，不是最先的。

- 心智模型回答「它是什么、不是什么」：资源、占用、归属、回收是不同状态，不是一个目录。
- 状态要有归属：谁持有、谁在用、什么算空闲。路径存在不等于你拥有它。
- 失败态要写：状态不符、残留占用、无法证明安全时，具体会看到什么。
- 边界要写：什么时候不该用这个工具，什么时候该手工做。

### 流程型

先写顺序，再写判断点；先写完成标准，再写工具。

- 步骤按执行顺序写，一步一个完成标准。
- 标出判断点：哪一步需要 AI 判断，哪一步必须由脚本保证。固定、脆弱、可重复的交给脚本；需要看上下文、权衡、取舍的留给 AI。
- 标出事实源：状态、数据、规则以什么为准；事实源不可用时怎么退。
- 标出人工确认点：哪些决定必须由人做，做完之后不要再打断。
- 写失败点：哪一步可能失败、失败时留下什么记录、哪些内容不能当成已完成。

### 倾向型

先写默认行为，再写目标行为；先写适用范围，再写例外。

- 默认行为要具体：agent 现在下意识会怎么做，错在哪里。
- 目标行为要可观察：能指出 agent 具体做什么、不做什么。
- 适用范围要写：哪些场景适用，哪些场景不适用。
- 触发词要写：用户会用什么说法触发；如果是模型自动触发，写进 description。
- 规则要少而硬：一条能覆盖的，不要写五条；写五条的，先问能不能合并成一条。
- 载体可以是一条规则，也可以是一组规则；形式不同，判据相同。

## 三个通用问题

每个技能都要回答，顺序不限。

1. **事实源是什么？** 状态、数据、规则以什么为准？它不可用时怎么办？
2. **哪些步骤必须由脚本保证？** 固定、脆弱、可重复的交给脚本；需要判断的留给 AI。脚本要自己处理错误，不把问题甩回给 AI。
3. **状态不符或失败时怎么办？** 不猜、不硬写、留下记录、退到更保守的做法。先确认自己拥有什么，再决定下一步。

## 写作规则

### 触发：description 是唯一的入口

- 模型可见的 description 写两件事：做什么，什么时候用。
- 用用户会说的词，不用内部术语。
- 宁可稍微主动：模型倾向于不用技能，而不是滥用技能。
- 不超过 1024 字符；正文才该有的细节不要放进来。
- 前半句说做什么，后半句说何时用；比如「当……时使用」。

### 上下文成本和认知成本

- 模型可见的 description 每轮都在上下文里；正文只在触发后进来；引用只在需要时读。
- 用户要记得有哪些技能、什么时候用，这是认知成本。
- 能自动触发就别让人记；只给人用的就别占上下文。调用方式见 [SKILL-MECHANICS.md](SKILL-MECHANICS.md)。

### 信息分层：正文写步骤，参考下沉

- 每条路径都要用的，放正文；只有部分情况才用的，放引用，并在正文写清「什么时候去读」。
- 引用一层深，不要引用套引用；超过 100 行的引用，开头放目录。
- 正文控制在 500 行 / 5000 tokens 以内；超了先下沉参考，再考虑拆文件。
- 同一个概念的定义、规则、例外放在一起，不要散落。

### 每一步都要有完成标准

- 完成标准要能判断「做完没有」。
- 标准要够狠：「每个调用点都核过」比「给出改动列表」更能逼出工作量。
- 标准模糊时，先把它写具体；不要靠「后面还有步骤」来催。

### 用一个短词承载一块行为

- 找一个模型已经认识的词，反复用；不要每次用一句话解释同一个概念。
- 短词在正文里锚定行为，在 description 里锚定触发。
- 不用否定句指路：「不要做 X」会把 X 拉进上下文；直接写「做 Y」。

### 剪枝：一个意思只留一处

- 同一件事只在一个地方写；其他地方指向它。
- 环境能查到的（目录结构、命令、配置），不要抄进技能；技能只写环境查不到的判断和坑。
- 逐句问：删掉这句，行为会变吗？不会就删整句。
- 时间敏感的信息不写；会过期的版本号、路径、人名不写。
- 技能会沉积：旧内容一层层留下。定期删，不要只加。

### 反模式

- 同一概念换着词说。
- 一次给太多选项；给默认，再给例外。
- 假设工具已经装好。
- 魔法数字没有解释。

## 改造：四种常见错位

1. **类型错**：用三类表重新判；重点和写法对不上，就是类型错。
2. **重点错**：重点埋在长流程里；读完不知道哪一段是必须的。
3. **通用问题缺**：三个通用问题有任何一个答不上来。
4. **臃肿**：用「信息分层」和「剪枝」两节过一遍。
