# 技能设计

技能是一次可预测的行为改变：同一个输入，agent 每次走同一条路。

判断顺序：agent 缺什么决定类型，类型决定正文该有什么，写作规则决定怎么落笔。

## 三类技能

| 类型 | agent 缺什么 | 正文写什么 |
|---|---|---|
| **工具型** | 不知道工具是什么、它处在什么状态 | 心智模型、用法、状态不符时、适用范围 |
| **流程型** | 每次执行顺序不一样、判断点说不清 | 顺序、脚本边界、完成标准、回环 |
| **倾向型** | 默认行为不对 | 现在会怎么做、该怎么做 |

多数技能兼几类；按主要矛盾排顺序，不按清单逐项填。

### 工具型

先写心智模型，再写命令。

- **心智模型**：一句话说清它是什么、不是什么，并能拿它预测下一步。写不出来，说明只抄了命令，没懂工具。
- **用法**：写 agent 实际要走的那条路径；哪一步要判断、怎么判断，说清楚。
- **状态不符时**：看到什么征兆说明现实和心智模型对不上，那时先核实再动手。
- **适用范围**：什么情况下用它，什么情况下换别的做法。

### 流程型

先写顺序，再写判断点，再写完成标准。

- **顺序**：说不清执行顺序的流程，写不成技能。
- **脚本边界**：固定、可重复、容易出错的步骤交给脚本；要看情况再定的留给 agent。每一步标出由谁执行。
- **完成标准**：每一步什么条件算做完，细节见下文「完成标准」。
- **回环**：流程会回到走过的步骤时，写明什么条件退出，否则就是无限循环。

### 倾向型

先写默认行为，再写目标行为。

- **默认行为**：agent 现在下意识会怎么做，错在哪。
- **目标行为**：换成一个可观察的动作，不是一句态度。

## 写作规则

### 指针：说清是什么、什么时候读

**上下文指针**是上下文里的一句引用，指向上下文外的材料，并写明什么时候去读。技能的 description 是指针，`AGENTS.md` 里的一行也是。指针的措辞决定 agent 够不够得到目标；必须读的材料配一句含糊的指针，每次运行都在赌。

指针写两件事：这份材料是什么，哪些情况该读它。一个触发条件只写一次，同义改写不算第二个分支。触发用的词放在最前面，那才是它起作用的位置。

### 两种成本

- **上下文成本**：常驻上下文的内容（description、`AGENTS.md` 的行）每轮都在花 token 和注意力，比正文更该剪。
- **认知成本**：人得记得有哪些技能、什么时候用哪个。这不是要压到最小的成本：人的判断力值钱的地方就该花。
- 自动触发：不写 `disable-model-invocation`，并写 description；agent 能自己发现，别的技能也能调用，代价是 description 永远占着上下文。
- 手动触发：写 `disable-model-invocation: true`；只有人能叫它，技能名的记忆落在人身上。手动技能多到记不住时，加一个路由技能，列出它们和各自的用途。

### 信息分层

文档里只有两种内容：**步骤**（按顺序做的事）和**参考**（要用时查的定义、规则、事实）。

位置分三档：正文里的步骤、正文里的参考、拆到别的文件靠指针够到的参考。

往上放太多，正文会肿，注意力被摊薄；往下推太多，agent 够不到真需要的东西。判据是分支：每条路径都要用的放正文，只有部分情况才用的推到指针后面。同一个概念的定义、规则、例外放一起，别散在各处。

### 完成标准

每一步的结束条件，两条都要满足：

- **能判断**：agent 分得出做完和没做完。含糊的标准会招来提前完成——注意力滑向「快做完了」。
- **够狠**：标准决定 agent 肯挖多深。「每个调用点都核过」逼出的工作量远多于「给出改动列表」。

标准模糊时先写具体；实在具体不了，再按下文「什么时候拆」把后续步骤移出视野。

### 什么时候拆

拆一份文档就多付一份指针或认知成本，只在拆得值时才拆：

- 按顺序拆：完成标准实在写不具体，而后续步骤又勾着 agent 赶前面这步时，把后面的步骤移出视野（拆给另一个 agent）。反过来，合并两段流程会把后面的步骤暴露给前面。
- 按调用方式拆：另一个技能要复用的参考，可以单独拆成自动技能。

### 引导词

**引导词**是模型预训练里见过的短词，agent 一边执行一边用它思考。它作为词反复出现（不重复解释），几轮下来锚住一整片行为，花的 token 最少。造词也行，但调不动先验，得用定义补上省不下的成本，优先找现成的词。

同一个概念只用一个词，并且 description、正文、代码里用同一个词，三处一致 agent 才连得起来。

指路时直接写目标行为：禁令会把被禁的行为拉进上下文，反而更显眼。

### 剪枝

- **一个意思只留一处**。重复既难维护，又会让一个意思在文档里的分量超过它真实的地位。
- **环境也是事实源**。目录结构、命令、配置从环境查得到的别抄进技能：抄了会过期。只写环境里查不到的——没写下来的约定、做某个选择的原因、配置不承认的坑。
- **逐句问**：删掉这句话行为会变吗？不会就删整句，别改措辞。
- **沉积**是默认结局：加进去安全，删掉看着危险，旧内容一层层留下。定期往回删。

## 改造检查

1. **类型错**：用三类表重判；正文的重点和类型对不上，就是类型错。
2. **重点错**：必须写的那几项埋在别的内容里，读完不知道哪个是重点。
3. **臃肿**：按信息分层和剪枝过一遍。
