# 技能设计

技能是一次可预测的行为改变：同一个输入，agent 每次走同一条路。

判断顺序：agent 缺什么，决定技能类型；技能类型，决定正文该有什么。

怎么把正文写得让 agent 读得懂，看 `writing-for-agents`（创建或编辑技能时自动加载）。本技能只定类型和正文重点，不重复它的规则。

## 三类技能

| 类型 | agent 缺什么 | 正文写什么 |
|---|---|---|
| **工具型** | 不知道工具是什么、它处在什么状态 | 心智模型、用法、状态不符时、适用范围 |
| **流程型** | 每次执行顺序不一样、判断点说不清 | 流程结构、顺序、脚本边界、完成标准 |
| **倾向型** | 默认行为不对 | 现在会怎么做、该怎么做 |

多数技能兼几类；按主要矛盾排顺序，不按清单逐项填。

### 工具型

先写心智模型，再写命令。

- **心智模型**：一句话说清它是什么、不是什么，并能拿它预测下一步。写不出来，说明只抄了命令，没懂工具。
- **用法**：写 agent 实际要走的那条路径；哪一步要判断、怎么判断，说清楚。
- **状态不符时**：看到什么征兆说明现实和心智模型对不上，那时先核实再动手。
- **适用范围**：什么情况下用它，什么情况下换别的做法。

### 流程型

先判流程结构，再写步骤。

按跨度判：一种结构跨过的步骤最多，它就是外层结构；剩下的部分按同样方式再判。

- **回环**：回到已经执行过的步骤 → **状态机**。写状态、转移条件、动作、失败态，并写明什么条件下不再回去。
- **多前置**：一步要等不止一个前置完成 → **DAG**。写节点、依赖、汇合条件。
- **都没有** → **线性**：沿一条主线推进，每步最多一个前置。写成编号步骤，判断点写成条件。

回环只在某个分支内部时，外层是 DAG，那个分支自己按状态机写；回环跨过几个并行分支时，外层是状态机，并行那段在里面按 DAG 写。

结构定了，再补三条：

- **顺序**：说不清执行顺序的流程，写不成技能。
- **脚本边界**：固定、可重复、容易出错的步骤交给脚本；要看情况再定的留给 agent。每一步标出由谁执行。
- **完成标准**：每一步什么条件算做完。缺少这一步，agent 会提前宣布完成。

### 倾向型

先写默认行为，再写目标行为。

- **默认行为**：agent 现在下意识会怎么做，错在哪。
- **目标行为**：换成一个可观察的动作，不是一句态度。

## 改造检查

1. **类型错**：用三类表重判；正文的重点和类型对不上，就是类型错。
2. **重点错**：该写的那几项埋在别的内容里，读完不知道哪个是重点。
3. **缺项**：三类表里对应类型的项缺了任何一个。
