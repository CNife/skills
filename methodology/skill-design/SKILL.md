# 技能设计

技能不是文档，是一次可预测的行为改变。**agent 缺什么，决定技能类型；每类的重点，决定正文；三个通用问题，决定它能不能执行。**

**范围**：本技能只管技能；写 `AGENTS.md` 或普通文档时，改用 `writing-for-agents`。

## 三类技能

| 类型 | agent 缺什么 | 重点 |
|---|---|---|
| **工具型** | 不知道工具的接口、状态和边界 | 心智模型和状态 |
| **流程型** | 步骤不稳、判断点不清 | 顺序和完成标准 |
| **倾向型** | 默认反应不对 | 默认行为的覆盖 |

### 工具型

先写心智模型，再写入口；先写状态归谁，再写命令。命令是最后的，不是最先的。

- 心智模型回答「它是什么、不是什么」：资源、占用、归属、回收是不同状态，不是一个目录。
- 状态要有归属：谁持有、谁在用、什么算空闲。路径存在不等于你拥有它。
- 失败态要写：状态不符、残留占用、无法证明安全时，具体会看到什么。
- 边界要写：什么情况下用这个工具，什么情况下手工做。
- 写坏的标志：只有命令清单，没有状态模型和「别手工做」的边界。

### 流程型

先写顺序，再写判断点；先写完成标准，再写工具。

- 步骤按执行顺序写，一步一个完成标准。
- 标出判断点：哪一步需要 AI 判断，哪一步必须由脚本保证。
- 标出事实源：在对应步骤旁写清。
- 标出人工确认点：哪些决定必须由人做，做完之后继续执行。
- 写失败点：哪一步可能失败。
- 判断点、事实源、失败点的判据，统一按「三个通用问题」回答。
- 写坏的标志：判断写死成脚本，或固定步骤留给 AI；步骤没有完成标准。

### 倾向型

先写默认行为，再写目标行为；先写适用范围，再写例外。

- 默认行为要具体：agent 现在下意识会怎么做，错在哪里。
- 目标行为要可观察：能指出 agent 具体做什么、不做什么。
- 适用范围要写：哪些场景适用，哪些场景不适用。
- 触发词要写：用户会用什么说法触发；如果是模型自动触发，写进 description。
- 载体可以是一条规则，也可以是一组规则，写法相同；能用一条覆盖的，先合并成一条。
- 写坏的标志：价值观散文，没有可观察的目标；规则不改变行为。

## 三个通用问题

每个技能都要回答，顺序不限。没有对应内容的，明确答「无」。

1. **事实源是什么？** 状态、数据、规则以什么为准？它不可用时怎么办？
2. **哪些动作必须由脚本保证？** 固定、脆弱、可重复的交给脚本；需要判断的留给 AI。
   - 脚本要自己处理错误，并给出可操作的提示。
   - 脚本里的数字给出判据或来源。
   - 先确认工具或依赖可用，再写命令。
3. **状态不符或失败时怎么办？** 先确认当前状态和已有信息；把不确定的部分记录下来；退到更保守的做法；只写已经确认的内容。

## 写作规则

### 自动触发：description 是模型的唯一入口

- 模型可见的 description 写两件事：做什么，什么时候用。
- 用用户会说的词；内部术语留在代码和文档里。
- 宁可稍微主动：模型倾向于不用技能，而不是滥用技能。
- 上限 1024 字符；正文才该有的细节留在正文。
- 前半句说做什么，后半句说何时用；比如「当……时使用」。

### 上下文成本和认知成本

- 自动触发付上下文成本，手动触发付认知成本；两种成本和取舍判据见 [SKILL-MECHANICS.md](SKILL-MECHANICS.md)，决定用哪种前先读。
- 手动技能多到记不住时，读 [SKILL-MECHANICS.md](SKILL-MECHANICS.md) 的「路由技能」。

### 信息分层：正文写步骤，参考下沉

- 每条路径都要用的，放正文；只有部分情况才用的，放引用，并在正文写清「什么时候去读」。
- 引用保持一层深；超过 100 行的引用，开头放目录。
- 正文控制在 500 行 / 5000 tokens 以内；超了先下沉参考。要拆成新的自动技能时，判据见 [SKILL-MECHANICS.md](SKILL-MECHANICS.md)。
- 同一个概念的定义、规则、例外放在一起。

### 每一步都要有完成标准

- 完成标准要能判断「做完没有」。
- 标准要够狠：「每个调用点都核过」比「给出改动列表」更能逼出工作量。
- 标准模糊时，先把它写具体；完成与否只看当前标准。

### 用一个短词承载一块行为

- 找一个模型已经认识的词，一个概念只用一个词，反复用。
- 短词在正文里锚定行为，在 description 里锚定触发。
- 指路时直接写目标行为：「做 Y」；禁令会把被禁行为拉进上下文。

### 给默认，再给例外

- 先给一个默认路径，再给例外；并列多个等价选项会让 agent 停在选择上。

### 剪枝：一个意思只留一处

- 同一件事只在一个地方写；其他地方指向它。
- 环境能查到的（目录结构、命令、配置），留在环境里；技能只写环境查不到的判断和坑。
- 逐句问：删掉这句，行为会变吗？不会就删整句。
- 写长期有效的信息；版本号、路径、人名这类会过期的东西，留在环境里。
- 技能会沉积：旧内容一层层留下。定期删旧，保持当前内容。

## 改造：四种常见错位

1. **类型错**：用三类表重新判；重点和写法对不上，就是类型错。
2. **重点错**：重点埋在长流程里；读完不知道哪一段是必须的。
3. **通用问题缺**：三个通用问题有任何一个答不上来。
4. **臃肿**：用「信息分层」和「剪枝」两节过一遍。
