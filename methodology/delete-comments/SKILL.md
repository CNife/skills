# 删除注释

注释只有两个去处：代码吸收它，或 ADR 收下它。留在代码里的注释，都是还没处理完的债。

清零的规则只有一条：命中的注释本身一律删除；区别只在于删之前把内容送到哪里。

## 范围

- 默认：默认分支上的全部第一方源码。
- 给了文件或目录：只处理这些。
- 说了「只看 diff」：当前分支相对默认分支（默认 `main`）的 diff，加工作区改动。

不算第一方源码，跳过：第三方与生成资产、依赖锁文件、测试 fixture、`docs/` 与仓库策略文档。

## 四类

| 类别 | 判据 | 删前送到 |
|---|---|---|
| 同义反复 | 只重复代码里看得见的名字、类型、常量、步骤；分区标题、逐字段释义 | 不送，直接删 |
| 过时 | 引用的符号、行为、界面规格已经不存在或已改变；含注释掉的旧代码 | 不送；现行规格归设计文档一处 |
| 借口 | 为敷衍实现开脱：空 catch 的理由、静默兜底的说明、手抄映射的辩解、「以后再说」 | issue：写清符号、现状、为什么错、验收行为 |
| 决策记录 | 代码和测试表达不出来的非显然约束、取舍、外部限制 | ADR：一条一段，带符号或文件指针 |

判不准时按顺序找证据：读邻近代码，追注释点名的符号、调用、配置，查外部依赖版本或平台行为。找不到活证据，按同义反复处理。

lint 抑制（`eslint-disable`、`@ts-ignore`、`# type: ignore`）同样先查被抑制的规则：压住真实缺陷的，删抑制并开 issue；只针对风格且规则本身有错的，保留并在报告里点名。

## 流程

1. **盘点**：用 `ast-grep run --lang <语言> --kind comment <路径>` 按语法树枚举注释（多数语言用 `comment`，Kotlin、Rust 用 `line_comment`、`block_comment`），再按范围过滤。语言不在 ast-grep 内时用该语言自己的解析器；正则扫描会把字符串、正则和 URL 里的符号当成注释。完成标准：范围内每个源码文件都有归属，清单里没有字符串或正则字面量。
2. **分片审计**：按目录切片；有并行子代理就每片派一个，交回 `文件:行 | 原文 | 类别 | 理由`，没有就按片顺序自己过。子代理只报告，不改代码。完成标准：每片都返回逐条结果，没有未归类的命中。
3. **复核**：每条命中都要落到一个类别。打回三类误判：把代码问题算成注释问题、把决策记录说成借口、把范围外文件算进来。被驳回的重审一次；第二次仍驳回就停下报告。完成标准：每条命中都有最终类别，重审次数进报告。
4. **迁决策**：决策记录写进 `docs/adr/`，没有就建 `0001-*.md`。完成标准：每条决策都有去处，ADR 与代码不重复同一事实。
5. **开 issue**：每个借口对应一个 issue，同一根因合并。创建前把标题和正文交给用户确认；建不了就落成报告里的待办。完成标准：每个借口都有链接或待办。
6. **删除**：只删注释行和注释块留下的空行；不合并空 catch、不改代码 token、不重排格式。完成标准：diff 里只有删除行。
7. **上棘轮**：仓库已有注释预算校验（按文件统计注释行 + 基线文件）就按它收紧。没有就提议：每文件默认预算 0、基线只记录例外、新增注释失败、只在删注释后用显式环境变量收紧；用户批准后按仓库主语言落地（单测或 lint），不批就跳过并列为未决。完成标准：预算只降不升，失败信息说明怎么收紧。
8. **验证**：跑范围最近的检查（单测、编译或 lint），再临时加一行注释确认棘轮变红，删掉后恢复绿。完成标准：检查通过，失败路径实测过。
9. **报告**：删除的注释行数、四类分布、ADR 新增条目、issue 链接、棘轮状态、预计减少的代码行数。完成标准：六项都有数，例外逐项列出。

## 例外

以下保留，其余清零：

- 许可与版权头：SPDX 标识、版权行等机器要读的元数据。
- Python shebang 与 PEP 723 依赖区块。
- Python 模块 docstring：它是运行时接口。
- 格式与编译指令：`// prettier-ignore`、`# fmt: off`、构建系统标记。
- 第三方代码、生成资产、测试 fixture。
- 库项目面向外部使用者的 API 契约注释（docstring、doc comment）；应用项目不适用。

新增例外同时写进 ADR，理由跟着例外走。
