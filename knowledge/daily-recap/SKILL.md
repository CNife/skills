# Daily Recap - 每日工作整理

将所有机器上的 Agent 会话整理为一份**主题聚合**的日报，写入 Obsidian 工作日志或个人日记。

**nmem 是 source of truth**：多台机器上的会话通过 nmem 同步，覆盖全部机器的全部会话。本地 jsonl 文件仅存在于当前机器，是**本机会话的内容增强来源**。

## 流程

### Step 0：确定目标工作日并检查数据来源

**目标工作日**：工作日窗口以 CST 04:00 为界 [工作日 04:00, 次日 04:00)，凌晨 00:00-04:00 的会话归前一工作日。"总结哪个工作日"由 `extract_today.py` 按 recap 时刻自动选择（分界规则见脚本 `choose_target_workday`），AI 用脚本输出 JSON 的 `date` 字段；整理指定工作日才显式传 `--date YYYY-MM-DD`。

**先确定目标工作日**（脚本自动选择）：

```bash
cd <skill目录> && uv run --script scripts/extract_today.py --min-msgs 10
# 跳过 stub 会话；仍含大量 title=null 会话则一次性提到 15，不反复重跑
```

不带 `--date`，脚本自动选择目标工作日并在输出 JSON 顶层 `date` 字段返回。**读这个 `date` 作为目标工作日，后续远程粗筛、候选表标题、时间窗口核实全部复用它**。整理历史日期才显式传 `--date YYYY-MM-DD`。

拿到 `date` 后立即回显：「整理目标工作日：{date}（脚本自动选择，改期用 `--date`）」，让日期错误第一轮就能被发现。用户纠正则带 `--date YYYY-MM-DD` 重跑脚本，用新 `date` 走后续流程。

脚本输出同时是本机会话证据集（04:00 窗口精确切分：粗筛 UTC 文件名前缀 + 读 session 行 timestamp 转 CST 判断）。

**远程**（nmem 是 source of truth）：

拿到 `date` 后用 `nmem_list_threads` 列举近期线程（`limit` 调大如 200，或分页跟随 `has_more`/`offset`），按返回的 `date`（日级导入日期，非会话时间，英文格式如 "Jul 18, 2026"）粗筛目标工作日 ±2 天纳入候选——按月份+日判断是否落在范围内；精确切分推迟到 Step 4 远程条目核实（批准后定向 `nmem_read_thread`）。

**降级**：`nmem_list_threads` 抛 `backend_unreachable`/`timeout`（后端不可达，插件已内部重试）-> Hard stop，见 `references/recovery-guide.md`：询问用户是否仅看本机会话。

**空集反证**：脚本 `total: 0` 且远程也无候选时，先反证--当前 daily-recap 会话本身必然在目标工作日窗口内（除非显式整理历史日期）。若本应有当前会话却 `total: 0`，结果可疑，排查窗口/路径/日期而非直接终止。仅当反证通过（确实无会话）才告知用户"目标工作日没有会话记录"并终止。

**分流**：

- 仅本机有数据 -> 跳过远程，进入 Step 1a
- 仅远程有候选 -> 纯远程：跳过 Step 1a，直接 1b
- 两路都有 -> 进入 Step 1

当前日报会话（本次整理本身）也在脚本输出中，无需此时排除--Step 2 分类时归入"当前日报"类，不纳入候选。

**完成条件**：目标工作日已回显，且证据集已确认非空（本机或远程至少一路有候选），或已告知用户"目标工作日没有会话记录"并终止。

### Step 1：收集并提取

两路会话分别处理：

#### 1a. 本机会话 - 引用 Step 0 脚本输出

Step 0 已运行的 `extract_today.py` 输出即为本机会话的**完整证据集**（标题、时间 CST、项目、消息量、首条用户消息、产出摘要），无需重跑。

参数备忘（Step 0 未带时可补跑）：`--exclude <uuid>` 排除指定 session；`--date YYYY-MM-DD`（或位置参数）指定目标工作日。

#### 1b. 远程会话识别（summary 级）

**UUID diff**：nmem 线程 id 去 `pi-`/`omp-` 前缀，与本机脚本输出 `session_id` 列表比对，差集即真远程会话（其他机器执行、本机无 jsonl）。

对真远程会话，用 `nmem_list_threads` 已返回的 `title`/`summary` 作为初步证据列出，标「📡 待核实」--summary 足以判断去向与主题域，但不含会话时间和原始对话，写入前需核实（Step 4）。

**完成条件**：真远程会话已识别并列出（summary 级），进入 Step 2 分类。

### Step 2：分类

分类只处理远程会话（本机会话已被脚本结构化）：

| 分类 | 判定 | 内容源 |
|------|------|--------|
| **本机会话** | UUID 在脚本输出中 | 脚本输出的结构化数据 + 原始 jsonl（需要时） |
| **远程会话** | UUID 仅在 nmem 中 | nmem summary（📡 待核实，Step 4 核实补充） |
| **当前日报** | 标题含"日报/daily-recap"关键词 | 标记"当前日报"并跳过 |

**完成条件**：每个会话已归入本机/远程/当前日报三类之一，无遗漏。

### Step 3：构建候选表（用户确认）

将所有证据整理为候选条目表，**直接按主题域分组**：

| # | 会话主题 | 主题域 | 来源 | 去向 | 理由 |
|:-:|----------|--------|:----:|:----:|------|
| 1 | HPC 巡检 | genome-assembly | 🖥️ | 工作日志 | 之江实验室日常工作 |
| 2 | 双语 HTML 转换 | learn-mattpocock | 📡 | 不记录 | 个人练习，无产出变化 |

去向：`工作日志` · `个人日记` · `不记录`
来源：🖥️ 本机 / 📡 其他机器

**呈现给用户确认**。用户修正去向或标记跳过后，仅批准的条目进入下一步。

**完成条件**：用户已确认或修正每个候选条目的去向。

### Step 4：主题聚合并输出日报

> **HITL**：叙事对齐（4b）和事实核验（4d）是判断分叉处，过人确认，不让 agent 自评后跳过。Step 3 候选表确认同为 HITL。

#### 4a. 扇出 subagent 按主题域并行收集产出物 + 证据

候选表确认后，**按主题域**扇出 subagent 并行收集（一个主题域一个 subagent，包揽该主题下所有会话）。subagent 只收集并返回证据包文本；日记写入由主 agent 在 4b 对齐、4d 核验通过后独占执行。

**扇出参数**：

- `agent: explorer`（工具层无 write/edit/bash，写入风险由选型消除）
- `systemPrompt`：传达步骤 1-5 的收集职责与返回格式
- `task`：主题域 + 会话清单（filepath / 时间 CST / 标题）+ 重点核实项；去向由主 agent Step 5 掌握，不入 task

每个 subagent 的收集步骤：

1. **读会话**：本机会话用 `ffgrep` 搜 jsonl 内的工具调用路径 + `read`（带 offset/limit）定向读关键行（explorer 无 bash，用这两个工具替代 jq/grep）；远程会话用 `nmem_read_thread`（`thread_id`，`offset: 0` 起续读）。
2. **自发现产出物路径**：从会话的工具调用里抽 read/write/edit 涉及的文件路径，筛出关键文档（方案/规格/issue/报告），`read` 它们确认内容。
3. **时间窗口核验**：`messages[0].timestamp` 转 CST，确认落在目标工作日窗口 [04:00, 次日 04:00)。窗口外剔除，输出注明「剔除：时间窗口外」。
4. **内容提取**：提取 summary 没有的结构化细节（关键决策、参数、产出物、数字），供 bullet 追溯。
5. **返回证据包文本**：每条含关键结论、带来源的数字、决策、建议的叙事角度。返回即止。

**降级**：若 subagent 无法访问 nmem 工具，远程会话改由主 agent 串行 `nmem_read_thread`，混合主题（本机+远程）的综合也落回主 agent。单会话读取失败标记「内容待补充」，不阻塞该主题域。

**完成条件**：每个批准的主题域都有一份证据包文本，每条关键结论/数字有原文或原文档出处。

#### 4b. 对齐门（HITL · 每次都拦）

主 agent 基于证据包，给一张**每主题域一句叙事角度**的表（这天的日记回答什么问题、各事件怎么串），**一轮**呈现给你确认或改。

- 4b 只确认叙事角度；bullet 细节与已有章节对齐留到 4c 写作 / Step 5 写入（日记未读无法提前判断）。
- 你改完角度后，才进入 4c 写作。

**完成条件**：每个主题域的叙事角度已确认。

#### 4c. 聚合写作

对确认角度的条目进行**主题聚合**--按主题域合并：

1. 语义相近的事件合并到同一个主题域下
2. 同一主题下的多个事件 -> 1 个标题 + 子 bullet 展开
3. 每个子 bullet 1-2 行，**只写结论和决策**
4. 按重要性排序：部署/功能交付在前，基础设施/配置在后，探索/学习最后
5. 不超过 6 个主题域（理想 3-5 个），无零散单事件段落

事件记录原则（6 种）：

- **实现了功能**：功能名称 + 核心特性 + 关键技术决策
- **修复了问题**：问题 + 根因 + 修复方式
- **做了决策**：决策内容 + 理由 + 放弃的替代方案
- **调研了方案**：调研对象 + 结论 + 选型判断（为什么选 A 不选 B）
- **部署/配置**：环境 + 关键参数 + 验证结果
- **验证假设/回答问题**：原始问题 + 验证方法 + 结论 + 下一步含义

**完成条件**：每个批准主题域已写成 1-2 行 bullet，每条对应一种事件记录原则。

#### 输出模板

标题层级遵循 `references/diary-rules.md` 变体规则（文件名已含日期，文件内一级标题是主题/子系统，不重复日期标题）。每个主题域一个一级标题，按重要性排序：

```markdown
# 主题域（work: 子系统名 / personal: 主题标题）

- 关键事件 bullet...
- 关键事件 bullet...
```

#### 写入前门禁

聚合草稿完成后、写入 Obsidian 前，逐项检查以下 3 个 blocker。任一不通过 -> 必须先修正：

| Blocker | 检查项 | 不通过则 |
|---------|--------|---------|
| ① 事实虚构 | 每条 bullet 能追溯到证据包中的具体来源（会话原文或关键文档）？远程条目需会话线程原文支撑，summary 不算可追溯来源。不写“根据习惯”“随手”“一般来说”等无来源内容 | 删除虚构内容 |
| ② 结构散乱 | 按主题域聚合而非按时间平铺？ | 重新聚合主题 |
| ③ 流程噪音 | 混入了 agent 操作日志或内部项目标签？包括：会话全景表、会话编号、来源标记、消息量、Git 提交、验证流程、阶段标记、配置路径，**以及内部项目标签（map/ticket/issue 编号、里程碑、生命周期阶段如 原型/验收/标定/闭环）**。另区分“完成了什么任务”与“产出了什么结论”--前者是任务状态（噪音），后者才是应写的结论，目标形状见上方事件记录原则 | 删除噪音，只保留人的结论和决策 |

**完成条件**：每个确认条目都归入一个主题域，无零散单事件；正文通过 3 blocker 门禁。

#### 4d. 核验（HITL）

门禁通过后、写入前，对**凡有可追溯来源的 bullet** 跑核验 subagent：让它对着证据包里的原文档/会话线程，逐条核对数字、百分比、公式、口径是否与来源一致。**数据密集条目必查**，纯定性条目可选。

**核验 subagent 参数**：

- `agent: reviewer`（只读 + bash 只读命令已内建，glm-5.2 适合逐条核对数字）
- `systemPrompt`：传达核验职责--对着证据包原文逐条核对数字/口径，报告不一致项
- `task`：证据包原文 + 待核验 bullet 清单（每条含声称的数字和来源出处）

核验 subagent 报告不一致项（数字错配、口径混淆、最高/最低写反等）；**发现不一致 -> HITL**：报告给你，你拍板怎么改，改完再写入。无不一致则直接进入 Step 5。

**完成条件**：所有数据密集条目已与来源核对一致，或已按你拍板修正。

### Step 5：写入 Obsidian

将聚合后的日报写入 Obsidian 工作日志或个人日记。

#### 5a. 选择变体

按候选表去向（工作日志/个人日记）确定变体。变体判断规则见 `references/diary-rules.md`：work（公司项目/部署运维/团队协作）vs personal（个人技术探索/学习/投资/生活/个人开源项目）。混合内容拆分到两个变体分别写入。

#### 5b. 获取日记上下文

```bash
cd <skill目录> && uv run --script scripts/obsidian-helper.py --vault <work|personal> [--date YYYY-MM-DD]
```

输出三段：DIARY_PATH/DATE、RECENT（近期 2-3 篇日记摘要，了解写作风格）、TODAY（今日日记全文）。日记不存在时脚本自动从模板创建。写入时**始终**传 `--date`（用 Step 0 的目标工作日），指向目标工作日的日记。

首次配置：脚本输出 `CONFIG_MISSING=true` 时，按打印的示例创建 `~/.config/cnife-skills/obsidian-diary.json`（含各 vault 的 base/diary_dir/template/exclude_meta），询问用户 vault 根目录后填入，重新运行脚本。

#### 5c. 补全式整合写入

**先读后写**：基于 TODAY 全文补全整合，不覆盖。新内容能塞进已有章节的不新开标题（Blocker ② 的「已有章节对齐」在此检查，Step 4 时日记未读无法判断）：

1. 已有章节 -> 在该章节末尾追加新 bullet，不重写已有内容
2. 新章节 -> 插入到已有章节之后（待办块之后，如有），按重要性排序
3. 用 Edit（patch）工具写入

**完成条件**：日记已补全式整合写入，新内容已与已有章节对齐。
