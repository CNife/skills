# 日记格式规则

包含 work（工作日志）和 personal（个人日记）两种变体的完整规则。
脚本通过 `--vault` 参数选择对应变体。

---

## Vault 路径

- 根目录：由配置文件 `~/.config/cnife-skills/obsidian-diary.json` 中的 `vaults.<variant>.base` 决定
- 日记目录：`{日记目录}/YYYY/MM/`（**目录名用纯数字，不带中文**）
- 文件命名：`YYYY年M月D日星期X.md`（如 `2026年4月17日星期五.md`，**只有文件名含中文日期字符**）
- 模板文件：`{日记目录}/{模板文件名}`

**⚠️ 常见错误**：不要将中文日期字符（`年`/`月`/`日`/`星期`）用在目录路径中。

| ❌ 错误 | ✅ 正确 |
|---------|--------|
| `{日记目录}/2026年/2026年5月21日星期四.md` | `{日记目录}/2026/05/2026年5月21日星期四.md` |
| `{日记目录}/2026年5月/2026年5月21日星期四.md` | `{日记目录}/2026/05/2026年5月21日星期四.md` |

完整路径示例：

```text
{base}/{日记目录}/2026/05/2026年5月21日星期四.md
         ───┬─── ┬ ─┬─ ───────┬────────
           项目  年 月    文件名（含中文日期）
```

---

## 模板内容

新日记文件由 `obsidian-helper.py` 从配置的模板复制（见 `~/.config/cnife-skills/obsidian-diary.json` 的 `vaults.<variant>.template`，默认 work 用 `{日记目录}/日志模板.md`、personal 用 `{日记目录}/日记模板.md`）。

**模板内容的唯一真相源是模板文件本身**：待办事项块等内容直接读模板文件，禁止在本文档或 agent 记忆中复述模板内容。模板文件缺失时脚本报错退出，不静默降级为手写。

## work（工作日志）变体规则

### 标题结构

- `# 子系统名` → 一级标题，粒度到具体子系统（如 `# OneReason MCP` 而非 `# OneReason`）
- `## 具体任务` → 二级标题，按独立交付物拆分（两个功能 = 两条，框架搭建 ≠ 工具实现）

为什么按子系统拆分？**工作日志会被分享给团队或作为日报素材。** 同事和管理层按子系统定位感兴趣的部分，不关心子系统之间的混杂内容。

### 任务状态 Emoji

- ✅ 已完成
- 🔄 进行中
- 🐛 Bug修复
- 🔍 调研
- 🚀 已部署
- 🤝 会议/协作

### 内容规则

每个交付物 1-2 行。简洁、只写结果、以子系统为维度。

### 好的写法

```text
✅ execute_cypher：只读查询 + 权限管控 + 结果序列化，经真实数据库验证
✅ 单阶段 Dockerfile（256MB），MCP 端点响应符合预期
✅ 确认 taplo-pre-commit 为 tamasfe/taplo 官方镜像仓库，非 fork
```

### 应避免的写法

```text
❌ 完成 Wave 2-4：权限管控、序列化、工具实现（阶段标签代替实际交付物）
❌ 4 轮最终验证全部 APPROVE，18 个测试用例全部通过（验证过程不是交付物）
❌ 创建 .dockerignore：排除 .git/.venv/__pycache__/.env/tests 等 12 项（配置细节在仓库里）
❌ 已提交并推送到 dev 分支（Git 操作不是人的产出）
❌ 沉淀 5 条项目规则到 AGENTS.md（模型间通信协议，不是人的工作成果）
```

## personal（个人日记）变体规则

### 标题结构

- `# 主题标题` → 按主题域分组（如 `# 金融研究` 而非 `# daisy 安装` + `# 个股分析` + `# 红利筛选`）
- 一个主题域下多个相关事件用 bullet 展开，每个 1-2 行

### 内容类型

- **技术类**：关键决策和结论，不需要实现细节
- **学习类**：学到了什么、下一步
- **生活类**：操作、观点、趣事

### 语气

比工作日志更轻松，可以保留个人观点和感受。这是刻意保持的特色，不要写成干巴巴的工作报告。

### 好例子 vs 坏例子

#### 主题聚合

```text
❌ 坏写法（流水账，按会话顺序平铺）：
# daisy-financial-research 技能上手
# 中创智领分析
# A 股红利质量筛选
# 投资分析

✅ 好写法（按主题域聚合，合并相关事件）：
# 金融研究
- 安装 daisy，覆盖 A 股/港股深度分析与估值建模
- 个股分析：中创智领（PE 7.76x）、太保（PE 6.7x）、东兴证券、川恒股份
- A 股红利筛选：Top 10 银行股包场，兴业银行 9% 股息率居首
```

#### 内联记录 vs 独立文档链接

```text
❌ 日记里展开全部细节：
- CouchDB 数据库名禁止连字符，所以用了 vault_work 而不是 vault-work
- CORS 报错是因为 nginx 不应当处理 CORS 头...

✅ 有独立文档时只写结论+链接，细节在文档里：
- CouchDB 3.4.3 跑在阿里云 ECS，踩坑记录 → [[技术方案/Obsidian同步方案-LiveSync深度调研]] §7
```

#### 语气

```text
❌ 工作报告调子：
完成了 CouchDB 部署工作，使用了 Docker 容器化方案，在阿里云 ECS 上运行。

✅ 保留个人感受和观点：
CouchDB 跑通了，终于摆脱了 Remotely Save 的 OAuth 中继依赖。
纯个人选择——不需要 E2EE 也不需要实时同步，Periodic + Batch Save 刚好。
```
