# 个人日记变体规则

## Vault 路径

- 根目录：`/mnt/c/Obsidian`（由配置文件 `~/.config/cnife-skills/obsidian-diary.json` 中的 `vaults.personal.base` 决定）
- 日记目录：`个人日记/YYYY/MM/`（**注意：目录名用纯数字，不带中文**）
- 文件命名：`YYYY年M月D日星期X.md`（如 `2026年4月17日星期五.md`，**只有文件名含中文日期字符**）
- 模板文件：`个人日记/日记模板.md`

**⚠️ 常见错误**：不要将中文日期字符（`年`/`月`/`日`/`星期`）用在目录路径中。

| ❌ 错误 | ✅ 正确 |
|---------|--------|
| `个人日记/2026年/2026年5月21日星期四.md` | `个人日记/2026/05/2026年5月21日星期四.md` |
| `个人日记/2026年5月/2026年5月21日星期四.md` | `个人日记/2026/05/2026年5月21日星期四.md` |

完整路径示例：

```text
/mnt/c/Obsidian/个人日记/2026/05/2026年5月21日星期四.md
                    ───┬─── ┬ ─┬─ ───────┬────────
                      项目  年 月    文件名（含中文日期）
```

## 模板内容

新日记文件从模板复制，模板仅包含一个 `# 待办事项` 标题和 tasks 查询块。

## 格式规则

### 标题结构

- `# 主题标题` → 按主题域分组（如 `# 金融研究` 而非 `# daisy 安装` + `# 个股分析` + `# 红利筛选`）
- 一个主题域下多个相关事件用 bullet 展开，每个 1-2 行

### 内容类型

- **技术类**：关键决策和结论，不需要实现细节
- **学习类**：学到了什么、下一步
- **生活类**：操作、观点、趣事

### 语气

比工作日志更轻松，可以保留个人观点和感受。这是刻意保持的特色，不要写成干巴巴的工作报告。

## 区分工作与个人

- 公司项目开发、部署、运维、正式会议 → 使用 work 变体
- 个人技术探索、学习笔记、投资复盘、生活记录 → 本变体
- 混合内容 → 只记录个人部分，末尾提示用户是否也需要工作日志

# 写好之后自检

写完后用这三问检查自己的输出。任何一项不通过都要修正后再确认。

## 一问：语气像不像在工作周报？

❌ 像周报：
- "完成了 CouchDB 部署工作，使用了 Docker 容器化方案，在阿里云 ECS 上运行"
- "经测试验证，同步功能正常，数据库连接无异常"

✅ 像人的日记：
- "CouchDB 跑通了，终于摆脱了 Remotely Save 的 OAuth 中继依赖"
- "纯个人选择——不需要 E2EE 也不需要实时同步，Periodic + Batch Save 刚好"

**怎么修**：加感受词（"终于"、"没想到"、"比想象中简单"）、加判断（为什么选这个不选那个）、用短句、保留口语感。

## 二问：是按主题分的，还是按时间排的？

❌ 按时间平铺（流水账）：
- 先装 daisy
- 又分析了中创智领
- 然后跑红利筛选
- 最后看了三只持仓

✅ 按主题聚合：
- **金融研究**：装了 daisy、分析了中创智领和持仓、跑了红利筛选
- **基础设施**：Git 备份、SMB 备份配好了

**怎么修**：先问自己"今天做了几件事？"（不是"今天先做了什么后做了什么"），合并同类项，一个主题一个 `#`。

## 三问：有没有不该写进来的东西？

❌ 噪音（AI 操作日志）：
- "已提交并推送到 main 分支"
- "N 轮最终验证全部 APPROVE"
- "沉淀 N 条规则到 AGENTS.md"

✅ 该写的：
- "功能上线了"（而非"已推送"）
- "MR 已创建交给老吴审查"（而非无意义的"N 轮验证"）
- 技术选型结论（而非 AGENTS.md 规则细节）

**怎么修**：每条内容问"这是人的工作成果，还是 agent 的操作记录？"——删掉 agent 操作，保留人的产出。
