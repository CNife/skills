# Local GitHub

`~/github` 是**参考库**：第三方仓库各一份长期本地副本，目录名是**规范名** `属主@仓库名`，大小写与 GitHub 一致。

读 GitHub 上的代码走本地副本——能 grep、能整目录读、离线可用。

## 拿路径

```bash
~/.agents/skills/local-github/scripts/manage-local-github.py ensure 属主/仓库名
```

stdout 只有本地绝对路径，直接拿去读；副本缺失时它自己克隆。

**完成标准**：拿到一个存在的目录，之后的读取都在这个目录里做。

## 命令

| 命令 | 作用 |
| --- | --- |
| `ensure <仓库>` | 给出本地路径：缺则浅克隆，有则直接给，不联网 |
| `ensure --fresh <仓库>` | 先补史并快进当前分支，再给路径 |
| `path <仓库>` | 只查本地，没有就非零退出 |
| `clone <仓库>` | 显式浅克隆；接受 `属主/仓库名`、`属主@仓库名` 或 GitHub 地址 |
| `sync` | 全库刷新：浅副本先补史，有上游的做快进（默认子命令） |
| `sync --keep-shallow` | 同上，但跳过补史，只推进浅副本的 tip |
| `unshallow <仓库>...` | 只补史、不刷新代码；`--all` 处理全部浅副本 |
| `list` | 按上次更新时间列出各仓库，标注浅副本与命名、origin 问题 |
| `rename` | 把裸名目录规范成 `属主@仓库名` |

`<仓库>` 一律是 `属主/仓库名`，大小写随意。

## 时机

- **新鲜度不作保证**：副本可能滞后任意久，需要上游最新内容时自己刷新——`ensure --fresh` 先补史并快进再给路径，`gh api` 可直接看远端。
- **新副本是浅副本**：`clone` / `ensure` 的首次克隆只取默认分支最新一层（`--depth 1 --no-tags`），为的是快；此时 `git log` 只有 1 个提交。下次 `sync`（或 `unshallow <仓库>`）补回当前分支的完整历史与全部 tag；`sync --keep-shallow` 跳过补史只推进 tip。
- **禁止修改 `~/github` 下的任何内容**：库里是参考资料，要改代码到库外另建工作副本。未提交改动不会阻止 `sync`：只要不与上游冲突，快进会保留它们；真冲突时 git 拒绝，`sync` 报「本地改动挡住更新」，领先上游的本地提交也只报告、不 reset。
- **根目录**：`LOCAL_GITHUB_ROOT` 环境变量，默认 `~/github`。
