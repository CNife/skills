# Prompt Craft

基于 OpenAI 提示词工程最佳实践，帮助用户优化已有 LLM 提示词。目标是让提示词更清晰、更可执行、更容易得到稳定输出，同时保留用户原本的任务意图、语言和风格。

## 工作流程

### 第一步：确认输入

先判断用户是否已经提供了要优化的提示词：

- 如果已经提供，直接进入审查。
- 如果没有提供，请用户先贴出原提示词。
- 如果原提示词存在，但任务目标、受众、输出格式或关键约束缺失，并且这些信息会明显影响改写质量，只追问必要的问题。

不要使用固定问卷。追问的目的只是补齐会影响改写方向的信息。

### 第二步：读取原则

读取 `references/principles.md`，把它作为提示词优化原则的单一来源。

只应用与当前提示词相关的原则。不要为了覆盖清单而强行输出 9 条完整审计；如果某条原则不适用，就跳过。

### 第三步：诊断问题

围绕用户提供的提示词，给出简短诊断：

- 哪些地方会导致模型误解、输出漂移或难以复用。
- 哪些相关原则可以改善这些问题。
- 哪些内容已经足够清楚，不需要为了“优化”而改动。

诊断要服务于改写，不要写成冗长报告。

### 第四步：生成改进版

输出完整、可直接复制使用的改进版提示词。

改写时遵循：

- 保留原提示词的语言和风格，除非用户明确要求翻译或换风格。
- 保留用户原始意图，不额外扩展任务范围。
- 将任务目标、上下文、约束和输出格式写得更具体。
- 对适合结构化输出的任务，补充清晰格式或示例。
- 对代码、查询或工具类任务，只在确实有帮助时加入引导词或执行边界。

### 第五步：交付结果

每次回复包含：

1. **诊断**：列出最相关的 2-5 个问题或改进点。
2. **改进版提示词**：给出完整新版本。
3. **改动说明**：简要说明关键改动对应的原则。

如果用户只想要最终版本，可以压缩诊断和说明，但不要省略完整改进版。

## 边界

- 不写入文件。
- 不询问保存路径。
- 不生成命令模板。
- 不把简单改写升级成完整技能设计或工作流设计。
- 不默认把中文改成英文，也不默认输出双语版本。
