# Daily Recap — 今日工作整理

将今天在某个项目上的所有会话、记忆和 git 提交整理成一份按主题组织的工作日报。核心是**合并分散的会话记录，按主题域聚合，而非按时间线平铺**。

## 前置条件

- 项目应在 Git 仓库内运行（`git log` 可用）
- Nowledge Mem CLI（`nmem`）可用且已登录
- 可选：Obsidian 日志写入需要 `obsidian-diary` skill 可用

## 流程

### Step 1：搜索 Nowledge Mem 上下文

搜索今日的记忆和线程。查询动词（query）用**项目名 + 工作/部署/开发**等通用词：

```bash
nmem --json m search "<项目关键词> 工作" -n 10
nmem --json t search "<项目关键词>" -n 5
```

**解读**：记下高分的记忆（≥0.6）和线程 ID 列表。此为后续验证的基线。

### Step 2：核查 Pi 会话文件

交叉验证 Nowledge Mem 是否覆盖了今天的全部会话：

```bash
ls -lt ~/.pi/agent/sessions/--<项目目录哈希>--/
```

筛选今天（当前日期）的文件。文件名中包含 UTC 时间戳（`YYYY-MM-DDTHH-MM-SS-mmmZ`），用 `date -d` 转成本地时间后再使用。

将每个文件名中的 UUID 与 Step 1 的线程 ID 匹配：

- 已匹配 → 该线程已被覆盖
- 未匹配 → **遗漏的会话**，可能是 `(new)` 前缀或较短的长描述

**完成标记**：列出所有遗漏的 thread ID。

### Step 3：加载遗漏的线程内容

对每个未匹配的线程（及部分匹配但内容不详的），逐段加载并提炼核心事件：

```bash
nmem --json t show "<thread_id>" --limit 5 --offset 0 --content-limit 1000
```

- 优先加载开头（获取目标）和中间段（发现关键决策/事件）
- 按需增加偏移量（offset）查看更多消息
- 每读一段，问：**这段产生了什么可记录的产出？**——提交、决策、Bug 修复、配置变更

**完成标记**：每个遗漏线程至少读到一个可记录的产出，**或**确认该线程无关（非本项目任务）。

### Step 4：记录候选（人工审核关口）

将 Step 1→3 收集的所有线索（记忆、线程产出、git 提交）整理为候选条目表：

| # | 会话/事件 | 项目域 | 建议去向 | 理由 |
|:-:|-----------|--------|----------|------|
| 1 | HPC 巡检 | genome-assembly | 工作日志 | 之江实验室日常工作 |
| 2 | 双语 HTML 转换 | learn-mattpocock | 不记录 | 个人练习，无产出变化 |

去向选项：`工作日志` · `个人日记` · `不记录`

**呈现给用户确认**。用户修正去向或标记跳过后，只有批准的条目进入后续聚合。

### Step 5：检查 Git 提交记录

```bash
git log --oneline --since="YYYY-MM-DD" --all
git log --format="%h %ad %s" --date=iso -N
```

按时间线列出今天的所有提交。标注 commit hash、时间、说明。

**完成标记**：今天所有提交已罗列。

### Step 6：按主题域聚合

这是最关键的步骤——**不做时间线平铺，只按主题域合并**。

1. **列举所有 distinct topics**：含记忆内容、线程产出、git 提交
2. **聚合归域**：语义相近的事件合并到同一个主题域下。判断依据：这些事是否属于同一个目的或领域？
   - 同一主题下的多个事件 → 1 个 `## 标题` + 子 bullet 展开
   - 不同域的事件 → 各自独立段落
3. **排序**：按重要性排序——通常部署/功能交付在前，基础设施/配置在后

每个事件的记录格式：

- **实现了功能**：功能名 + 核心特性 + 决策
- **修复了问题**：问题 + 根因 + 修复方式
- **做了决策**：决策内容 + 理由 + 放弃的方案
- **部署/配置**：环境 + 关键参数 + 验证结果

**完成标记**：所有事件聚合为不超过 6 个主题域（理想 3-5 个），无零散单事件段落。

### Step 7：呈现结果

按以下结构输出日报（语言与用户当前语言一致）：

```markdown
# 📋 YYYY-MM-DD 工作日志

> 项目：`<repo>` | 当前 commit: `<hash>`

## 会话全景（共 N 个）

| # | 时间 | 主题 | 消息量 | 状态 |
|:-:|:---:|------|:-----:|:----:|
| 1 | hh:mm | 主题 | N条 | ✅ |

## 一、上午/下午：按时间段分组（可选）

### 🔹 主题域 1（核心工作）

关键事件 bullet...

### 🔹 主题域 2

关键事件 bullet...

## 三、Git 提交汇总（N commits）

| 时间 | Commit | 说明 |
|:---:|:------:|-------|

## 四、关键发现与决策

1. bullet...
```

### Step 8：可选 — 写入 Obsidian 工作日志

询问用户是否需要写入工作日志。如果用户确认：

- 优先调用 `obsidian-diary` skill（如已安装）
- 不可用时，直接读取目标日记文件并用 Edit 工具追加或更新对应段落

不主动写入——等待用户确认。

## 恢复指南

| 症状 | 原因 | 操作 |
|------|------|------|
| nmem 返回 0 结果 | 今日无 Nowledge Mem 记录 | 直接跳到 Step 2 查会话文件 |
| 会话文件目录有多个项目 | 当前分支涉及多个项目目录 | 对每个项目目录重复 Step 2→5，在 Step 6 合并 |
| git log --since 无输出 | commit 标记日期不匹配 | 去掉 --since，用 `git log -20` 看最近提交 |
| obsidian-diary 不可用 | skill 未安装 | 直接用 Edit 工具追加，见 Step 8 fallback |
